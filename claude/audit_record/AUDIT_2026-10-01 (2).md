# QuantumWuxia — Progress Audit

**Date:** 2026-10-01 · **Baseline audited:** `main` at `e4d9554` (after PR #25, Phase 5.3)
**Method:** read `doc/*`, cloned the repo, ran `typecheck`, `test:simulation`, `build`, and the test files CI does not run; traced the store → pipeline → resolver → narrator path by hand.

## 1. Verdict

The **architecture is sound and unusually disciplined for a prototype**: a deterministic resolver behind one visible boundary, injectable rolls, a machine-readable event ledger, bounded NPC agency, and a genuine world-truth / player-knowledge split. The design docs are coherent and the code mostly honours them.

But on `main` today **the project does not typecheck, does not build under `tsc`, and every simulation test fails** — a single missing `{` in `validateState.ts` — and the live game does not yet exercise most of the simulation, because the world a player actually plays in is **a single location** with no Wuxia content. The engine is ahead of the game.

| Check | `main` as found | After this patch |
|---|---|---|
| `npm run typecheck` | **fail** (syntax error, then a type error) | pass |
| `npm run test:simulation` | **fail** (suite cannot load) | **49 / 49 pass** |
| `npm run build` | fail | pass |
| Causality v3/v4/v5 tests | never executed by CI; the 4 Jianghu suites crash on load | run in CI, 18 / 18 |

## 2. What is genuinely good

- **The simulation contract is real, not aspirational.** `resolveAction` clones input, range-checks the roll, validates state before and after, and returns structured events + ledger entries. The test suite proves non-mutation and determinism.
- **One boundary** (`simulationBoundary.ts`) with adapters kept narrow, and an explicit, documented list of compatibility shortcuts (`constitution ← strength`, `mana ↔ Qi`).
- **Knowledge discipline**: NPC knowledge context is restricted to authored/witnessed/granted ledger entries; investigation agency reads NPC-known rumors, not global truth. This is the hardest pillar to get right and it is done well.
- **Bounded simulation** (3 NPC actions/tick, one causal step per chain per turn) prevents runaway cost.
- Docs record *decisions and non-goals*, not just features.

## 4. Remaining findings (not fixed), by priority

### P1 — The live game is not yet the simulation

1. **The playable world is one room.** In live play `locationIds` is seeded from `[gameState.location]` (`actionPipeline.ts` → `simulationMigration.ts`), so every `travel` is blocked; `createDefaultJianghu` also places *every* NPC at the player's start. Markets, rumors, factions' territory and travel goals have nowhere to happen.
2. **Character creation is generic fantasy.** Warrior/Rogue/Mage/Paladin and Human/Elf/Dwarf; the fallback opening location is `'Dungeon Cell'`; the Wuxia identity exists only in the narrator prompt. The `Spellbook` screen is mana-based, contradicting "Qi is not mana".
3. **The narrator is told almost nothing about what happened.** It receives `[Resolved action: success] The action succeeds; the narrator may now describe…` — not the events or ledger. It cannot describe real consequences, which invites exactly the invention the prompt forbids.
4. **Randomness is not injectable at the product level.** `resolvePlayerAction` defaults the roll to `Math.random()`; no seed is stored, so a bug report cannot be replayed (Bible §4). `Combat.tsx` is a **separate legacy combat system** with its own `Math.random` and no engine imports — a second source of truth. `revive()` still mutates legacy and simulation state separately (already tracked in the workplan).
5. **AI boundary is only half built.** No runtime schema validation (`parseLLMResponse` trusts `parsed.choices`); no separate intent-interpreter / choice-generator contracts; the opening scene accepts an unvalidated LLM `locationChange`. Intent interpretation is keyword-based, so "bribe the guard" becomes `other`, and `inferTarget` needs the *full* NPC name ("Elder Bai" does not match "Elder Bai Qingshan").

### P2 — Depth gaps against the Game Bible

6. **The resolver is thin.** Difficulty is a table by action kind; `attack` has no opponent, damage or injuries beyond one backlash on a high-risk failure; HP never decreases, so defeat/death (§7) cannot occur. `techniqueId`, martial-art mastery, rank, and Qi cost (`qiCost` defaults to 0 for every kind) are never consulted.
7. **Travel has no distance.** Only "does the id exist"; fixed `timeCost`. (The new content pack provides a weighted graph for this.)
8. **"The world acts while you are elsewhere" is partial.** Rumor propagation and market updates key off the *player's* location; NPC agency does move NPCs and trade at their own locations.
9. **Cultivation is nearly inert**: stage, meridian integrity and bottleneck only affect Qi recovery; no advancement mechanic.

### P3 — Hygiene

10. README and several docs still describe "Realm of Echoes"; `IMPLEMENTATION_PLAN_SIMULATION_CORE_V1.md` points at `src/engine/simulation-core-v1/`, which does not exist; the Bible's target folders (`src/world/…`, `src/character/…`, `src/ai/…`) are not followed yet (this patch starts `src/world/content/`).
11. Five `SESSION*_SUMMARY.md` files and `COMPLETE_SUMMARY.md` at the repo root duplicate `doc/`; `package.json` name is `sandbox-workspace`; `MartialArtType` contains a typo, `'qinqong'` (kept in the content pack to stay compatible — rename to `qinggong` when convenient); `placeholder.md` files remain.
12. Workplan §11 acceptance boxes are still unchecked although the first three (typecheck, build, engine tests) are now satisfied.

## 5. Content added (the "enrichment")

New folder `src/world/content/`, pure data + pure builders, no React/Zustand/LLM dependencies:

| File | Contents |
|---|---|
| `locations.ts` | 10 locations of the **Nine Rivers Jianghu** with a weighted travel graph, terrain, inspectable features, hazards; `travelDays()` |
| `martialArts.ts` | 9 arts with techniques, lineage, requirements, counters, risks, mutual incompatibilities; `instantiateArt()` |
| `fantasyLayer.ts` | Declares the supernatural layer per Bible §3: presets `pure_wuxia`, `hidden_arcana`, `living_legends` |
| `jianghuSeed.ts` | 6 factions + relations, 12 NPCs (goals, fears, **secrets**, dialogue voice), NPC relationships, 3 obligations, 6 rumors (true / distorted / false), 3 world events, 4 markets; `createWuxiaJianghu()` |
| `origins.ts` | 6 origins, each with a hook and **five contextual opening choices** |
| `index.ts` | `createWuxiaSimulation(originId, fantasyPreset)` → a complete, valid `SimulationState` |

**Designed story engine, not a plot.** The seed plants interlocking tensions and lets the simulation resolve them: Jade Hall's missing final sword volume (Elder Bai suspects the disciple who actually took it, Gu Wen; the street informant saw a Jade Hall robe); the Ferry Toll Dispute (the toll funds bribes to Marshal Zhao, who skims grain, which a rumor distorts into "selling to bandits"); a healer whose Crimson Lotus past is a low-credibility rumor; a needle-master who needs the Sunken Archive's codex to save her sister. Every secret is stored as NPC state, so the narrator can only reveal it through the knowledge system.

**Fantasy is a switch, not a default.** `pure_wuxia` removes the fox-spirit ferry singer, the immortal archivist, two locations, two rumors, one origin and the Foxfire art; `living_legends` restores them. Spirit arts are a distinct tradition and declared incompatible with Nine-Bell Breathing, never reusing Qi rules.

**Tests** (`test/simulation/wuxia-content.test.ts`, run by CI): all cross-references resolve; travel graph connected & symmetric; art incompatibilities mutual; builders deterministic and copy-isolated; fantasy gating; every origin's start state validates; **every opening choice × 3 rolls runs through the real interpreter and resolver** without mutating input or invalidating state; a 25-turn scripted campaign is reproducible.

## 6. Recommended next steps

1. **Wire the world in (small, high value).** On new game, build the simulation with `createWuxiaSimulation(origin)` and store it as `gameState.simulation`; `ensureSimulationState` already honours an existing valid state. This fixes findings 1 and 2 without touching the resolver.
2. **Replace the Warrior/Mage/Elf creation screen** with an origin picker over `ORIGINS`; show its five opening choices on turn 1.
3. **Give the narrator the ledger.** Pass a compact digest of this turn's events (and only player-known ones) instead of a generic summary.
4. **Seed the RNG** and store the seed + roll in the ledger so any turn is replayable; migrate `Combat.tsx` onto an engine `attack` that actually has opponents, damage and injuries.
5. **Make the resolver use the content**: techniques and Qi costs, art mastery/counters, travel distance from `TRAVEL_EDGES`, injury consequences — each as a tested, ledger-emitting rule.
6. **Add schema validation** (a small hand-rolled validator is enough) for LLM output and an LLM-assisted intent interpreter that only proposes a `ProposedAction`.
7. Delete or archive the stale scripts/summaries and update the README.

## 7. Follow-up applied: the authored world is now the live game

- `Character` gains optional `originId` / `fantasyPreset`.
- `CharacterCreation` is now a two-step flow: choose a name and supernatural level, then choose an authored origin.
- `startNewGame` builds the simulation with `createWuxiaSimulation`, starts at the origin's location, and uses authored opening choices. The LLM narrates the opening scenario but cannot move the player or replace those choices.

- New opening helpers provide the authored scenario and the legacy-character compatibility adapter.

Findings 1 and 2 in section 4 are resolved. Still open: the narrator event digest, seeded RNG, legacy Combat migration, LLM schema validation, and legacy HP/mana versus simulation HP/Qi duplication.

## 8. Follow-up applied: the narrator now hears what the player perceived

**Gap found:** the engine already tracked player knowledge (`rumor.knownBy`, `knownRumorIds`, `knowledgeRecords`), but nothing ever told the player anything: a successful conversation changed trust by +1 and nothing else, so the narrator had to invent what NPCs said.

- `src/engine/npcDisclosure.ts`: on a **successful** `talk`, the NPC shares at most one rumor they know and the player does not (highest credibility, ties by id). Recorded as a `world.fact_discovered` event with provenance (`via`), a knowledge record, and `knownRumorIds`. Secrets are never disclosed here. Failed or partial conversations teach nothing.
- `src/engine/narratorDigest.ts`: a pure **player-perception filter** over the resolution. It includes the action and outcome, only events the player witnessed (travel, hearsay told to them, injuries), who is visibly present, the observable public situation at the location, and the target NPC's speaking voice. It never includes NPC secrets, goals, fears, offscreen NPC actions or faction bookkeeping. It ends with explicit narration rules.
- Presentation data (NPC voices, location features) stays in the content layer and is passed in via `buildDigestOptions()`; the engine does not import content.
- The store sends the digest for origin characters instead of "The action succeeds…". The context prompt shows Qi and Origin instead of Mana, Race, Level and Gold for them.
- Tests (`test/simulation/narrator-digest.test.ts`): disclosure with provenance, failure teaches nothing, repeat talk yields "nothing new", hearsay wording, travel and public situation, determinism and non-mutation, and a **leak guard** that runs every origin × opening choice × 3 rolls and fails if any NPC secret, goal description, or non-public fear, or the name of an offscreen NPC the player was not told about, appears in the digest. Suite: 58 / 58.

**New finding (pacing, not changed):** every starting world event's causal chain completes within about 4 turns, including "The Autumn Assembly Approaches" (expires turn 60). Chains are capped at 3 steps by design (v4), so the seed's slow-burn tensions resolve far faster than their authored timescale. Options: raise the step cap per event kind, add a `pace` field to world events, or let chain steps wait several turns. This is an engine design decision, so I left it for you.

**Still open:** LLM output schema validation and later-turn `locationChange` (unvalidated), seeded rolls, legacy `Combat.tsx`, legacy-vs-simulation HP/mana duplication, resolver depth (techniques, Qi costs, damage).
