# QuantumWuxia — Progress Audit

**Date:** 2026-10-01 · **Baseline audited:** `main` at `e4d9554` (after PR #25, Phase 5.3)
**Method:** read `doc/*`, cloned the repo, ran `typecheck`, `test:simulation`, `build`, and the test files CI does not run; traced the store → pipeline → resolver → narrator path by hand.

## 1. Verdict

The **architecture is sound and unusually disciplined for a prototype**: a deterministic resolver behind one visible boundary, injectable rolls, a machine-readable event ledger, bounded NPC agency, and a genuine world-truth / player-knowledge split. The design docs are coherent and the code mostly honours them.

But on `main` today **the project does not typecheck, does not build under `tsc`, and every simulation test fails** — a single missing `{` in `validateState.ts` — and the live game does not yet exercise most of the simulation, because the world a player actually plays in is **a single location** with no Wuxia content. The engine is ahead of the game.

| Check | `main` as found | After this patch |
|---|---|---|
| `npm run typecheck` | **fail** (syntax error, then a type error) | pass |
| `npm run test:simulation` | **fail** (suite cannot load) | **49 / 49 pass** |
| `npm run build` | fail | pass |
| Causality v3/v4/v5 tests | never executed by CI; the 4 Jianghu suites crash on load | run in CI, 18 / 18 |

## 2. What is genuinely good

- **The simulation contract is real, not aspirational.** `resolveAction` clones input, range-checks the roll, validates state before and after, and returns structured events + ledger entries. The test suite proves non-mutation and determinism.
- **One boundary** (`simulationBoundary.ts`) with adapters kept narrow, and an explicit, documented list of compatibility shortcuts (`constitution ← strength`, `mana ↔ Qi`).
- **Knowledge discipline**: NPC knowledge context is restricted to authored/witnessed/granted ledger entries; investigation agency reads NPC-known rumors, not global truth. This is the hardest pillar to get right and it is done well.
- **Bounded simulation** (3 NPC actions/tick, one causal step per chain per turn) prevents runaway cost.
- Docs record *decisions and non-goals*, not just features.

## 4. Remaining findings (not fixed), by priority

### P1 — The live game is not yet the simulation

1. **The playable world is one room.** In live play `locationIds` is seeded from `[gameState.location]` (`actionPipeline.ts` → `simulationMigration.ts`), so every `travel` is blocked; `createDefaultJianghu` also places *every* NPC at the player's start. Markets, rumors, factions' territory and travel goals have nowhere to happen.
2. **Character creation is generic fantasy.** Warrior/Rogue/Mage/Paladin and Human/Elf/Dwarf; the fallback opening location is `'Dungeon Cell'`; the Wuxia identity exists only in the narrator prompt. The `Spellbook` screen is mana-based, contradicting "Qi is not mana".
3. **The narrator is told almost nothing about what happened.** It receives `[Resolved action: success] The action succeeds; the narrator may now describe…` — not the events or ledger. It cannot describe real consequences, which invites exactly the invention the prompt forbids.
4. **Randomness is not injectable at the product level.** `resolvePlayerAction` defaults the roll to `Math.random()`; no seed is stored, so a bug report cannot be replayed (Bible §4). `Combat.tsx` is a **separate legacy combat system** with its own `Math.random` and no engine imports — a second source of truth. `revive()` still mutates legacy and simulation state separately (already tracked in the workplan).
5. **AI boundary is only half built.** No runtime schema validation (`parseLLMResponse` trusts `parsed.choices`); no separate intent-interpreter / choice-generator contracts; the opening scene accepts an unvalidated LLM `locationChange`. Intent interpretation is keyword-based, so "bribe the guard" becomes `other`, and `inferTarget` needs the *full* NPC name ("Elder Bai" does not match "Elder Bai Qingshan").

### P2 — Depth gaps against the Game Bible

6. **The resolver is thin.** Difficulty is a table by action kind; `attack` has no opponent, damage or injuries beyond one backlash on a high-risk failure; HP never decreases, so defeat/death (§7) cannot occur. `techniqueId`, martial-art mastery, rank, and Qi cost (`qiCost` defaults to 0 for every kind) are never consulted.
7. **Travel has no distance.** Only "does the id exist"; fixed `timeCost`. (The new content pack provides a weighted graph for this.)
8. **"The world acts while you are elsewhere" is partial.** Rumor propagation and market updates key off the *player's* location; NPC agency does move NPCs and trade at their own locations.
9. **Cultivation is nearly inert**: stage, meridian integrity and bottleneck only affect Qi recovery; no advancement mechanic.

### P3 — Hygiene

10. README and several docs still describe "Realm of Echoes"; `IMPLEMENTATION_PLAN_SIMULATION_CORE_V1.md` points at `src/engine/simulation-core-v1/`, which does not exist; the Bible's target folders (`src/world/…`, `src/character/…`, `src/ai/…`) are not followed yet (this patch starts `src/world/content/`).
11. Five `SESSION*_SUMMARY.md` files and `COMPLETE_SUMMARY.md` at the repo root duplicate `doc/`; `package.json` name is `sandbox-workspace`; `MartialArtType` contains a typo, `'qinqong'` (kept in the content pack to stay compatible — rename to `qinggong` when convenient); `placeholder.md` files remain.
12. Workplan §11 acceptance boxes are still unchecked although the first three (typecheck, build, engine tests) are now satisfied.

## 6. Recommended next steps

1. **Wire the world in (small, high value).** On new game, build the simulation with `createWuxiaSimulation(origin)` and store it as `gameState.simulation`; `ensureSimulationState` already honours an existing valid state. This fixes findings 1 and 2 without touching the resolver.
2. **Replace the Warrior/Mage/Elf creation screen** with an origin picker over `ORIGINS`; show its five opening choices on turn 1.
3. **Give the narrator the ledger.** Pass a compact digest of this turn's events (and only player-known ones) instead of a generic summary.
4. **Seed the RNG** and store the seed + roll in the ledger so any turn is replayable; migrate `Combat.tsx` onto an engine `attack` that actually has opponents, damage and injuries.
5. **Make the resolver use the content**: techniques and Qi costs, art mastery/counters, travel distance from `TRAVEL_EDGES`, injury consequences — each as a tested, ledger-emitting rule.
6. **Add schema validation** (a small hand-rolled validator is enough) for LLM output and an LLM-assisted intent interpreter that only proposes a `ProposedAction`.
7. Delete or archive the stale scripts/summaries and update the README.

## 8. Follow-up applied: the narrator now hears what the player perceived

**Gap found:** the engine already tracked player knowledge (`rumor.knownBy`, `knownRumorIds`, `knowledgeRecords`), but nothing ever told the player anything: a successful conversation changed trust by +1 and nothing else, so the narrator had to invent what NPCs said.

- `src/engine/npcDisclosure.ts`: on a **successful** `talk`, the NPC shares at most one rumor they know and the player does not (highest credibility, ties by id). Recorded as a `world.fact_discovered` event with provenance (`via`), a knowledge record, and `knownRumorIds`. Secrets are never disclosed here. Failed or partial conversations teach nothing.
- `src/engine/narratorDigest.ts`: a pure **player-perception filter** over the resolution. It includes the action and outcome, only events the player witnessed (travel, hearsay told to them, injuries), who is visibly present, the observable public situation at the location, and the target NPC's speaking voice. It never includes NPC secrets, goals, fears, offscreen NPC actions or faction bookkeeping. It ends with explicit narration rules.
- Presentation data (NPC voices, location features) stays in the content layer and is passed in via `buildDigestOptions()`; the engine does not import content.
- The store sends the digest for origin characters instead of "The action succeeds…". The context prompt shows Qi and Origin instead of Mana, Race, Level and Gold for them.
- Tests (`test/simulation/narrator-digest.test.ts`): disclosure with provenance, failure teaches nothing, repeat talk yields "nothing new", hearsay wording, travel and public situation, determinism and non-mutation, and a **leak guard** that runs every origin × opening choice × 3 rolls and fails if any NPC secret, goal description, or non-public fear, or the name of an offscreen NPC the player was not told about, appears in the digest. Suite: 58 / 58.

**New finding (pacing, not changed):** every starting world event's causal chain completes within about 4 turns, including "The Autumn Assembly Approaches" (expires turn 60). Chains are capped at 3 steps by design (v4), so the seed's slow-burn tensions resolve far faster than their authored timescale. Options: raise the step cap per event kind, add a `pace` field to world events, or let chain steps wait several turns. This is an engine design decision, so I left it for you.

**Still open:** seeded rolls, legacy `Combat.tsx`, legacy-vs-simulation HP/mana duplication, resolver depth (techniques, Qi costs, damage).


## 9. Follow-up applied: pacing, and a validated AI boundary

**Correction to §4 finding 5:** I earlier wrote that a later-turn `locationChange` from the LLM was applied unvalidated. That was wrong: the store only reads `stateUpdates.locationChange` when starting a new game, and for origin characters that value is overwritten with the authored start. The real gaps were the parser, below.

### Pacing (`src/engine/jianghu*.ts`, seed)
- `WorldEventState.pace?: { steps, interval }` (bounded 1-12 stages, 1-20 turns; omitted = original 3 stages, 1 per turn). `chainPace()` is the single source; V4 and V5 both use it for cadence and completion.
- Mid stages of a paced faction/economic chain keep adding pressure; the local NPC mood erosion keeps its original two-stage bound.
- **Bug found:** faction `internalTension` fell by 1 every turn unconditionally, so it always drained to 0 and no slow-burn could build. It now cools 1 every third turn, and not at all while the faction is party to an active event. (This changes tuning for every game, not only authored events.)
- Seed paces: Ferry Toll Dispute 5 stages / 4 turns, Fever Season 4 / 6, Autumn Assembly 6 / 8. In a 70-turn run they complete on turns 21, 25 and 49 (previously all within ~4 turns). Jade Hall tension ends at 53 instead of 0.
- **Open finding:** V5 causal branching (escalate / de-escalate / confirm / false, location conditions, faction and market reactions) never runs in live play: V4 advances every chain first and sets the shared `nextCheckTurn`, which makes V5 ineligible. 70 live turns produced 0 `causal_branch_selected` events. V5 is only exercised by unit tests that build chains by hand. Activating it is a design decision (its default branch for low-severity faction events is "de-escalate", which would end the toll dispute early), so it is untouched apart from honouring `pace`.

### AI boundary (`src/ai/validateNarration.ts`)
- Replaces the greedy `\{[\s\S]*\}` parse, which broke whenever the model emitted two objects or braces after the JSON.
- Balanced-object extraction (string- and escape-aware), then validation: narrative must be a non-empty string (truncated JSON is salvaged, plain prose accepted, capped at 4000 chars on a sentence boundary); choices are renumbered 1..5, risk normalised, deduped, trimmed, capped and padded with distinct stock choices; **every `stateUpdates` field is dropped except a validated `locationChange`**, so the model cannot grant HP, gold, items or skills even if the UI is extended later.
- `llmService` shares one `callProvider` and one `narrate()` (previously duplicated twice); an unusable response is retried once, and repairs are logged.
- The opening prompt no longer says "level 1 Human" or lists legacy STR/AGI stats for origin characters.
- The retry path needs a live provider and is not unit-tested; the validator itself is (9 tests including a 500-case junk-input totality check).

Suite: 74 / 74 (+16 this round).

## 11. v5 additions

### Finale hooks (`src/engine/finale.ts`, `src/world/content/finales.ts`)
- A world event can carry a `finale`: serializable data of ordered outcomes, each with conditions (player presence, player knowledge, faction tension/hostility, NPC alive/disposition, market scarcity) and effects (adjust faction / relation / NPC / market, add NPC goal, spread rumor at named locations, start a follow-up event). The first outcome whose conditions all hold wins; the last must be unconditional. No randomness, no LLM.
- It fires when the event's causal chain completes (V4), ends the event, and emits `world.finale_resolved`. If the player is at the event's location they witness it: ledger witnesses, an `observation` knowledge record, and the narrator digest/fallback describe it. If not, nothing is told to them; the news exists only as rumors at the named places.
- Cascades are bounded: `start_event` skips an id that already exists, so a finale chain cannot loop.
- Digest foreshadowing: a local event with a finale says it will "come to a head very soon / before long" (deliberately fuzzy, never a countdown).
- Seven authored finales (three seeded events plus four follow-ups), calibrated on a passive run: Toll Dispute → `ferry-blockade` (turn 21) → `blockade-lifted` (37); Fever Season → `fever-epidemic` (25) → `shortage-eased` (41); Autumn Assembly → `hall-schism` (49) → `uneasy-truce` (74). Engaging changes the outcome: being present with enough goodwill gives `toll-mediated` or `healer-rallied`, and being at Jade Hall knowing the volume is missing with Elder Bai's trust gives `volume-exposed`.
- Goodwill decays while a faction dispute builds (stages 2-3), so trust has to be maintained: the integration test needs conversations both early and just before the finale.

### Also in v5
- `src/ai/fallbackNarrator.ts`, `src/ai/choiceGenerator.ts`, `src/engine/rng.ts`, and the store's `narrateResolvedTurn` (see §10).
- `useIntent` now sends the digest for origin characters too (only `makeChoice` did before).
- `llmService.narrate` throws if no usable narrative survives the retry, so the store can fall back.

### Known limits of v5
- After about turn 75 in passive play the seeded events are all resolved and nothing starts new ones; V3 only spawns faction-conflict events when hostility is at least 70. A world-event proposer (§13) is the missing piece.
- Finale outcomes cannot kill an NPC, change a relationship's trust/respect separately from disposition, or start a quest.
- Choice generation and fallback narration are tested against all six origins' first twelve turns, not against the full space of states.
- Nothing here was played in a browser.


## 12. v6: martial depth and defeat (Bible §6, §7, pillar 4)

**Corrections to earlier audit text.** (1) `Combat.tsx` is dead code (see §10, §7 row). (2) I wrote that the engine had "no Face": the player has a `wuxia.social.face` value (0-100) that only a successful `talk` changed (+1). Face for NPCs, and Face per context, are still absent. (3) §10 pillar 4 and the §6 row below are superseded by this section.

**Bug found and fixed:** the intent interpreter turned any "with / use / using X" into a `techniqueId`, and the contract rejects a technique the player does not own, so *any* casual phrase ("attack the guard with my sword", "meditate using breathing exercises") threw an error, and in the store that discarded the turn. The interpreter now resolves the phrase to a technique the character actually owns (by id, technique name, or art name) and drops it otherwise.

### What changed
- **Techniques and requirements are enforced.** A named technique costs its Qi (previously every action cost 0 Qi), is blocked when Qi is short, and is blocked until the parent art reaches its `minMastery`. An unnamed strike costs nothing.
- **A new `train` action** ("practise the Azure River Sword"): the missing advancement method. It raises art and technique mastery with diminishing returns (3, 2, 1 per success as mastery climbs), costs Qi and fatigue, and failure teaches nothing. Locked techniques open as mastery grows (tested: 40 practice turns unlock Whirlpool Bind).
- **`attack` against a person is a real exchange.** The target must be present and alive (otherwise blocked; before, it "succeeded" with no effect). Difficulty comes from the opponent's power; the player's edge is attributes (fatigue and injury adjusted), art power, technique mastery, and a ±10 style counter. Opponent power is authored for the 12 seed NPCs and derived (bounded) for anyone else.
- **Style counters are structured, not prose.** `strongAgainstArts` / `counteredByArts` on arts, `arts` on NPCs, authored as pairs and tested for validity. The digest tells the narrator when a style had the upper hand.
- **Losing costs something.** Failure and partial success cost HP (reduced by constitution, scaled by risk posture) and add a located injury (head, torso, arm, leg or internal) with a severity and healing time.
- **Injuries now matter mechanically:** arm/head wounds penalise fighting and practice, leg wounds raise travel and stealth difficulty, internal wounds slow Qi recovery, and resting speeds healing. (Previously nothing but a flat attribute penalty read injuries.)
- **Defeat is a new situation, not an end screen** (§7): `mercy` (left alive, battered) always in a friendly bout or at a monastery or healer or from someone who likes you; `robbed` (two possessions taken); `detained` for the garrison (everything confiscated); and `killed` only when the player attacked a master (power 70+) with lethal, high-risk intent and lost by a wide margin. Survivors are left at 15-20% HP and lose Face. Monks never kill.
- **Friendly bouts exist** ("challenge X to a friendly duel", "spar"): milder damage and injuries, no grudge, no faction penalty, no bystander anger, Face gained or lost, and defeat is always mercy. This also fixes a double count: the older assault fallout in `jianghu.ts` now skips honourable bouts, and the fight-specific fallout adds on top of it exactly once.
- **Mastery cannot be farmed on bystanders**: beating someone with power under 30 teaches nothing.
- **Death is final for origin characters.** `revive()` does nothing for them and the death screen hides "Revive"; loading a save or a new game remain. Legacy characters are unchanged.
- The narrator digest and fallback narrator now report fights, wounds (in plain words: "your right leg"), defeat, and mastery gains, without opponent power or secrets (test-guarded). The choice generator offers practice and a fair duel.

## 13. v7: the time model (Bible §11) and the framework/content split

**Design rule adopted for this and later work:** the framework (`src/engine`, `src/ai`) provides systems; a setting's content (`src/world/content`) is replaceable data; and what actually happens in a game (story progression, which skills the character learns, how NPCs change) comes from the player's decisions and free-text intents run through those systems. `test/simulation/architecture.test.ts` now enforces it: the framework may not import content, UI, stores or network code, may not call `Math.random`/`Date.now` (the one entropy source is `rng.randomSeed`), and may not contain any authored place/person/faction/art/plot id. Known exception: the small placeholder world in `createDefaultJianghu` (`engine/jianghu.ts`), kept for legacy games and old tests.

**Where earlier work leans toward authored story** (your call whether to trim it): the three seeded world events with their seven finales are seed content, but they are only data and every outcome is chosen from player-influenced state (presence, goodwill, knowledge). The origins' "hooks" and the NPC secrets are authored. Nothing in the framework requires any of them, and an empty world still runs.

### What changed
- **One clock.** `world.turn` is now measured in ticks of four hours (six per day). Date, season, year and time of day are derived from it (`engine/clock.ts`), so there is nothing to drift. A game opts in with `world.clock`; worlds without it (older saves, bare test fixtures) count ticks but feel no day, night or weather, so their behaviour is unchanged. `GameState.turnCount` still counts the player's actions.
- **Real distances.** The authored roads are engine data (`world.map`); travel time is the shortest route (a day is six ticks), stretched by weather. A place with no road is blocked at no cost. Before, any known place was one tick away.
- **The player is on the road while travelling** and the world ticks every step: rumors spread, NPCs run errands, slow events advance, and nothing is witnessed (a finale at the destination mid-journey is not seen).
- **Deterministic weather** (`engine/weather.ts`): a pure function of (seed, day, season, climate), in two-day spells, with climate tables (mountain, cold, marsh, river...). It slows travel, makes stealth easier and looking harder, and adds fatigue outdoors. Nothing is stored, so it is replayable.
- **Darkness and sleep.** Night helps stealth (-10 difficulty) and hampers inspection (+10). NPCs sleep in the small hours by default; an explicit routine overrides it (the ferry captain sleeps by day, the archivist never sleeps). Talking to a sleeper is blocked with no time passing, and the choice generator offers "Rest until afternoon when Captain Ma Tie will be up" instead of a doomed conversation.
- **Open-ended time intents**: "rest until dawn", "sleep overnight", "wait for a watch", "rest for two days", "meditate until midnight" (bounded to four days). Rest and meditation now scale with the time spent, and wounds heal with the passing ticks (rest doubles it).
- **NPC movement takes time** (`engine/routine.ts`). Routines, homes and travel goals all walk the map; an NPC on the road is in no place. Departures and arrivals the player could see become events the narrator hears ("Su Mian sets out for Moonwell Grove."). Goals can open later (`notBefore`) and can make the destination a new home (`settle`).
- **Fixed on the way:** (1) an old rule teleported any NPC who was not with the player to a faction territory every fifth turn, which would also have pulled story-relocated NPCs back; it is replaced by routines. (2) Keyword matching read substrings inside words: I observed "Inspect the camphor tree shrine" read as a rest action once "camp" became a keyword, and by the same logic "forest" contains "rest"; keywords now match only at the start of a word. (3) A finale's `moveTo` now relocates an NPC properly (new home, old routine dropped).
- Narration: the digest and fallback narrator now carry the time of day, weather, journey length, sleepers, blocked reasons ("X is asleep. No time passed.") and visible arrivals and departures. The side panel shows the date, time and weather.
- Origins can open at a chosen time of day so their first choices are playable (the ferry opens in the afternoon or evening, when the captain and the singer are awake). Saves from before the calendar get the clock, roads and routines on their next action (`upgradeWuxiaWorld`, idempotent, keeps story relocations).
